Motivação

Teste manual × teste automatizado

🙋

Teste manual

  • Uma pessoa segue os passos do caso de teste com mouse e teclado.
  • Bom para explorar, avaliar usabilidade e testar algo que muda muito.
  • Lento e cansativo quando precisa ser repetido a cada nova versão.
🤖

Teste automatizado

  • Um programa executa os mesmos passos e confere o resultado sozinho.
  • Rápido, repetível e sem distração: ideal para regressão.
  • Exige esforço inicial para escrever e manutenção quando a tela muda.
Lembre

Automatizar não substitui o raciocínio do QA. O script só confere o que alguém decidiu que deveria ser conferido, a partir dos requisitos.

A ferramenta

O que é o Selenium?

Uma biblioteca gratuita que permite que um programa controle um navegador de verdade: abrir páginas, digitar, clicar e ler o que aparece na tela, como um usuário faria.

🐍

Seu script Python

O arquivo teste.py diz o que fazer: “abra a Wikipedia”, “digite IA”.

→
🔌

WebDriver

O “tradutor” (chromedriver) que transforma os comandos em ações no navegador.

→
🌐

Navegador

O Chrome abre na sua tela e executa tudo sozinho, passo a passo.

Linguagens: Python, Java, C#, JavaScript…

Navegadores: Chrome, Firefox, Edge, Safari.

Tipo de teste: caixa preta, nível de sistema, pela interface.

Parte 1 · Ambiente virtual

O que é o venv?

Uma pasta isolada com um Python só para este projeto. As bibliotecas instaladas ficam dentro dela, e não no computador inteiro.

  • Sem conflito: o projeto A usa Selenium 4.25 e o projeto B usa outra versão, sem um quebrar o outro.
  • Organização: dá para apagar a pasta venv e criar de novo a qualquer momento.
  • Sem permissão de administrador: tudo é instalado dentro do projeto.
# 1. criar (uma vez só, dentro da pasta projeto) $ python3 -m venv venv # 2. ativar (toda vez que abrir o terminal) $ source venv/bin/activate # macOS / Linux > venv\Scripts\activate # Windows # 3. ativado: o nome aparece antes do prompt (venv) $

-m venv = rode o módulo venv · o último venv = nome da pasta que será criada · deactivate sai do ambiente.

Parte 1 · Dependências

O arquivo requirements.txt

É a lista de compras do projeto: diz quais bibliotecas (e quais versões) ele precisa para rodar.

# requirements.txt selenium>=4.25
EscritaSignificado

# instala tudo o que está na lista (venv) $ pip install -r requirements.txt # confere o que foi instalado (venv) $ pip list

Por que ele é importante?

Qualquer colega (ou o professor, ou o servidor de testes) clona o projeto e, com um comando, tem exatamente o mesmo ambiente. Sem ele, cada um instala “do seu jeito” e o teste que passa na sua máquina falha na do outro.

-r = “read”: leia os pacotes deste arquivo.

Selenium Manager

Desde a versão 4.6, o Selenium baixa sozinho o chromedriver certo para o seu Chrome. Antes, era preciso baixar e configurar manualmente.

Parte 3

Como achar
um campo

O Selenium não “vê” a tela como nós. Ele encontra cada campo, botão e texto pelo código HTML da página.

Parte 3 · Inspecionar elemento

Descobrindo o HTML do campo de busca

1

Abra a Wikipedia no Chrome.

2

Clique com o botão direito na barra de pesquisa → Inspecionar (ou F12).

3

O DevTools abre com a tag do campo destacada.

4

Procure um atributo único e estável: id, name…

<input class="cdx-text-input__input" type="search" name="search" placeholder="Pesquisar na Wikipédia" autocomplete="off">

Tag input = campo de digitação. Atributos = pares nome="valor". O destacado name="search" é o que vamos usar no código:

find_element(By.NAME, "search")

Parte 3 · Localizadores

As formas de achar: By

Localizador · procura por…HTML de referência · em amarelo, o que o localizador usaExemplo no Python
By.IDatributo id (deveria ser único) <h1 id="firstHeading">Inteligência artificial</h1> find_element(By.ID, "firstHeading")
By.NAMEatributo name (formulários) <input type="search" name="search"> find_element(By.NAME, "search")
By.CLASS_NAMEuma classe CSS <input class="mw-searchInput" type="search"> find_element(By.CLASS_NAME, "mw-searchInput")
By.CSS_SELECTORtag, #id, .classe, [atributo] <input type="search" name="search"> find_element(By.CSS_SELECTOR, "input[name='search']")
By.XPATHcaminho no HTML, até pelo texto <h1 id="firstHeading">Inteligência artificial</h1> find_element(By.XPATH, "//h1[text()='Inteligência artificial']")
By.LINK_TEXTtexto exato de um link <a href="/wiki/Wikipédia:Página_principal">Página principal</a> find_element(By.LINK_TEXT, "Página principal")
By.TAG_NAMEnome da tag <h1 id="firstHeading">Inteligência artificial</h1> find_element(By.TAG_NAME, "h1")
Ordem de preferência

ID → NAME → CSS → XPATH. Quanto mais simples e estável, menos o teste quebra quando a página muda.

Parte 3 · Buscar na página

find_element e seus parâmetros

campo = navegador.find_element(By.NAME, "search")
1º parâmetro

Estratégia

Como procurar: By.ID, By.NAME, By.XPATH… Vem de from selenium.webdriver.common.by import By.

2º parâmetro

Valor

O que procurar: o texto do atributo, sempre entre aspas. Precisa ser igual ao HTML.

Retorno

WebElement

Um objeto que representa o campo. É nele que vamos digitar, clicar e ler.

find_element (singular) → devolve o primeiro encontrado. Se não achar: NoSuchElementException

find_elements (plural) → devolve uma lista com todos. Se não achar: lista vazia [], sem erro.

Parte 3 · Interagir com o elemento

Como digitar, apertar teclas e clicar

from selenium.webdriver.common.keys import Keys campo = navegador.find_element(By.NAME, "search") campo.clear() # apaga campo.send_keys("Inteligência artificial") campo.send_keys(Keys.ENTER) # tecla # ou tudo de uma vez: campo.send_keys("Inteligência artificial" + Keys.ENTER)

Keys tem as teclas especiais: ENTER, TAB, ESCAPE, BACKSPACE, ARROW_DOWN…

MétodoO que faz
.send_keys("texto")Digita no campo, letra por letra, como um teclado
.clear()Apaga o que já estiver escrito
.click()Clica no elemento (botão, link, produto)
.submit()Envia o formulário do campo
.textLê o texto visível do elemento
.get_attribute("value")Lê um atributo (ex.: o que foi digitado)
.is_displayed()True se está visível na tela

Parte 4

Esperando a
página responder

O script é muito mais rápido que a página. Se ele procurar um campo que ainda não apareceu, o teste quebra.

Parte 4 · Sincronização

sleep × WebDriverWait

⏱

Espera fixa · sleep(3)

Para o programa por exatamente 3 segundos, aconteça o que acontecer.

pode ser poucopode ser demais

Útil para demonstração (ver o que está acontecendo), mas deixa o teste lento e instável.

🎯

Espera inteligente · WebDriverWait

Verifica a condição várias vezes e segue assim que ela for verdadeira, até um tempo máximo.

rápidoconfiável

Se o tempo máximo acabar: TimeoutException e o teste falha.

espera = WebDriverWait(navegador, 10, ignored_exceptions=[StaleElementReferenceException]) # ① qual navegador ② máximo em segundos ③ erros que não devem parar a espera (opcional)
Parte 4 · Condições de espera

espera.until(...) e o EC

from selenium.webdriver.support import \ expected_conditions as EC titulo = espera.until( EC.visibility_of_element_located( (By.ID, "firstHeading") ) )

Atenção aos parênteses duplos: a condição recebe um único parâmetro, uma tupla (By.ID, "firstHeading").

until repete a verificação (a cada 0,5 s) e devolve o elemento quando a condição for verdadeira.

Condição EC.Espera até…
presence_of_element_locatedo elemento existir no HTML
visibility_of_element_locatedexistir e estar visível
element_to_be_clickableestar visível e habilitado para clique
title_contains("texto")o título da aba conter o texto
url_contains("texto")o endereço conter o texto
text_to_be_present_in_elemento elemento mostrar um texto

Parte 5 · Um problema real

Por que o StaleElementReferenceException?

1

A página carrega e o Selenium acha a barra de pesquisa.

→
2

Um JavaScript da Wikipedia recria a barra logo em seguida. A antiga some.

→
💥

O send_keys tenta digitar na barra que não existe mais: elemento “velho” (stale).

A solução que usamos

Colocar a busca e a digitação dentro da função pesquisar. Se o erro acontecer, o WebDriverWait chama a função de novo, que acha a barra nova.

Lição de QA

Páginas modernas mudam depois de carregar. Teste automatizado precisa esperar e tentar de novo, não confiar que a tela já está pronta.

Parte 5 · Rodando o teste

Passou ou falhou?

Passou
(venv) $ python teste.py TESTE PASSOU: artigo aberto = Inteligência artificial Pressione ENTER para fechar o navegador...

O Chrome abre, a busca é digitada sozinha e o artigo aparece.

Falhou
TERMO_BUSCA = "inteligência artificial" # i minúsculo AssertionError: Esperado 'inteligência artificial', mas a página mostrou 'Inteligência artificial'

A Wikipedia abre o artigo certo, mas o título vem com I maiúsculo. O assert compara texto exato e aponta a diferença.

Importante

Um teste sem assert só “passeia” pela página. É a verificação que transforma o script em teste.
